智训引擎 · 工业模型自进化 Harness 项目说明书

一、作品概述

本作品对应赛题的三类工业模型续训任务（A 分类 / B 回归 / C 回归）。 我们提供一个只读镜像，通过平台协议完成多轮"提出假设 → 续训 → 平台测量 → 选择产物"的闭环， 每轮在父模型基础上小步更新，指标不劣化时才向前推进。

二、总体流程

start 帧 ──> 读取历史记录与漂移 ──> 平台模型给出本轮决策
         ──> 按数据集策略：A/C 安全续训，B 固定复现链
         ──> 平台测量验证指标
         ──> A/C 未优于父模型：自动回退（epochs/2、lr/2）再测
         ──> 择优提交候选或保留父产物 ──> save_state ──> finish

每轮至少发生一次真实模型调用，model_call_ids 全部来自平台回执； 选择理由、假设与变更说明随 finish 一并提交。

三、关键设计

1. 决策来自平台模型

contestlib/decision.py 把数据集、指标方向、历史 before/after、尝试记录和漂移摘要 组织成消息，要求模型只返回 JSON（epochs、learning_rate、hypothesis、change_summary、reason）。 解析失败时使用保守默认值，保证流程不中断。

2. 安全训练 safe_train

主方案未优于父模型时，自动用一半 epochs 和一半学习率在 round-XX-alt 重训； 两次都不优于父模型，则 keep_parent，提交的选中产物仍为父检查点，避免指标回退。

3. 数据集策略

A：采纳预算 10 轮、epochs 下限 2，逐轮小步续训； B：前 3 次采纳固定 5 轮 / 0.0005，走到已验证的稳定可见点后停训，仅保留父产物； C：采纳预算 1 轮、epochs 下限 2，其余轮次不训练。 预算用尽后仍每轮真实调用平台模型并 finish，保证协议完整，同时显著降低 CPU 消耗。 B 的固定链不以复现旧记录的隐藏指标为目标——试运行 #6 证明同一检查点的 B 隐藏指标 在不同试运行间不可比（见实验日志），因此 B 以稳定可见点 + 低资源为目标。

4. 漂移检测

对训练集与验证集的特征分布做统计对比，把分类占比变化、数值均值/方差变化写入 本轮记录和平台配置，作为后续决策依据。

5. 状态管理

每轮把选中检查点与完整 records 写入原生状态目录；下一轮读出历史记录， 模型据此判断是否继续小步更新还是保留父模型。

  • A 的公开验证可见 Macro F1 可达 0.97，但隐藏上限稳定在 0.88 附近，可见涨幅不迁移。
  • B 的可见指标与隐藏指标严重脱钩；同一检查点（可见链 658.13 → 663.14 → 652.57 逐位复现） 在 R1 与 R6/R7 的隐藏 RMSE 分别为 318.69 与 679.36。R6、R7 的 B 隐藏值逐位相同， 说明同一检查点在相邻试运行中可复现，R1 的 318.69 属于异常记录或不同隐藏划分； B 只能以稳定检查点 + 资源效率为目标，不再追 226/319 的旧记录。

  • 平台对同一产物展示的可见指标存在 ±3~4 复测抖动，该列不能用于跨轮比较。

B 3 / 10 367.78s RMSE 679.36

合计 14 / 30 3,313.50s —
  • Token：输入 27,433 + 输出 17,018 = 44,451，折合 1,481.7 Token/轮；每轮只调用一次平台模型。
  • 标注：额外人工标注 0 次；只使用平台公开训练集/验证集标签。SFT 的 13 条标签由 132 次网格实测自动生成，没有引入人工标注成本。
  • 单位增益：B 用 368s 走到与 R6 逐位相同的稳定点，是三条链路中单位算力收益最高的； A 用 1,049s 达到隐藏上限 0.880；C 的 1,897s 是算力大头，但 1 轮与 2 轮隐藏指标持平， 预算 1 已是稳定配置中成本最低的选择。
  • 与 R6 相比，R7 策略未变，CPU 下降 1%，Token 减少 129，指标无实质变化， 符合稳健性改动不改训练路径的预期。

6. 工业落地价值

方案面向传感器批次漂移、跨设备/跨工况的轻量工业模型：CPU-only、离线运行、无需 API Key， 可直接部署在边缘网关或产线工控机；每轮只产生一个小于 16MiB 的检查点，状态可续跑、产物可回滚。 预算与 epochs 下限把更新频率和算力锁死，避免模型在无收益时持续训练；全量 records 与平台测量值 可审计，满足工业场景对可解释、可回滚和零人工干预的要求。

五、微调过程

1. 监督数据来自网格实测

对 A/B/C × 每个历史状态，跑 epochs × learning_rate 网格（initial 12 组， 后续状态各 8 组），标签取验证指标最优的组合，共 132 次真实训练。 没有提升的状态不进训练集。

2. 两轮迭代

v2 13 rank 32，10 步，lr 5e-5 1.503 → 0.568 trio://run_ibgiij7ethtz/sampler_weights/aiplus-v2

3. 微调后评测对比（2 轮累计）

数据集 基线 SFT v1 SFT v2
A（越高越好） +0.0118 +0.0053 +0.0031
B（越低越好） −11.29 −21.47 −27.74
C（越低越好） −1.234 −1.199 −0.772

结论：v2 学会"保守小步"，B 的收益接近基线的 2.5 倍； 但仍存在"每轮都答 2 轮"的模式坍缩，A 的持续增长未学会， 说明状态到决策的条件映射需要更强的状态差异与更弱的拟合，是下一轮工作方向。

实验记录：https://swanlab.cn/@1839229675/aiplus-harness （含 sft-v1 / sft-v2 训练曲线与三轮评测运行）。

4. 当前定位

试运行表明，隐藏指标主要由 harness 的数据集策略（预算 / 固定链）决定， 单轮决策文本的影响有限。SFT v2 仍负责每轮的假设、理由与参数建议， 但 B/C 的实际训练配置由 harness 覆盖。后续若要继续微调，应改为 "给定候选让模型选择"的决策形式，避免 13 条样本造成的模式坍缩。

六、资源与合规

  • 训练与预测只在 /workspace 写文件，/app、/previous、/state 只读。
  • 只使用平台提供的公开训练集和验证集；验证集只用于测量与选择，不并入梯度训练。
  • 镜像内不包含任何 API Key；模型访问全部走平台 rnd.model() 或本地传输层。
  • 单轮候选文件数、体积均受 rnd.limits 约束，本次只提交 checkpoint.npz。
  • 训练异常时保留父产物并完成轮次；状态目录使用唯一名称，读取时清洗非法记录。
