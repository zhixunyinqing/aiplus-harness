智训引擎 R8 · 系统运行说明

一、运行环境

  • 平台：Linux/amd64 容器，CPU-only；不依赖 GPU、CUDA 或外部网络。
  • 镜像基础：python:3.12-slim；Python 3.12；numpy==1.26.4；contest_harness SDK 1.0.4。
  • 资源：镜像约 281MB；默认 2 个 CPU 线程（BASELINE_CPU_THREADS=2）。
  • 平台入口固定为 /app/harness.py，子命令为 describe、train、predict。
  • 镜像内不包含 API Key；模型调用只走平台 rnd.model() 或本地传输层。

二、构建与启动

# 从平台已验收的 aiplus-harness:0.1 派生，只覆盖 /app
docker build -f Dockerfile.rebuild --platform linux/amd64 -t aiplus-harness:r8 .
docker save -o harness-r8.tar aiplus-harness:r8

# 平台/本地加载与自检
docker load -i harness-r8.tar
docker run --rm aiplus-harness:r8      # 输出一行 describe JSON

平台按帧驱动：train 从标准输入读取 start 帧，predict 从标准输入逐行读取样本； 正常结束返回码为 0，所有 RPC 均带平台回执。

三、配置参数

参数 默认值 说明
CONTEST_WORK /workspace 唯一可写工作目录
CONTEST_SUBMISSION contest_submission 训练/预测回调模块
CONTEST_PREVIOUS_DIR 无 本地回环时的父产物目录
CONTEST_ARTIFACT_PATH /model/checkpoint.npz 预测时选中的检查点
CONTEST_PREDICTION_CONTEXT 无 平台预测上下文 JSON
CONTEST_DATASET_KEY / CONTEST_TASK 无 数据集与任务类型
BASELINE_CPU_THREADS 2 BLAS/OpenMP 线程数

策略常量在 app/contest_submission.py：A 采纳预算 10、epochs 下限 2， 采纳判据为“候选必须优于历史最佳可见值”，未越过时保留父产物，连续 3 轮未采纳后停训； B 前 3 次采纳固定 5 epochs / lr 0.0005 后停训；C 采纳预算 1、epochs 下限 2。 不训练的轮次跳过漂移统计，直接保留父产物。 决策调用 temperature=0.2，max_tokens=min(400, 平台上限)；提示词只带最近 3 轮， 每轮假设与说明各限 60 字。

四、输入输出

  • describe：输出一行 JSON，包含 protocol、model_access、sdk、sdk_version、tasks。
  • train：读取 start 帧（任务、父产物、公开数据路径、历史与预算），每轮调用一次平台模型， 提交至多一个 checkpoint.npz 候选，保存 state，发送 finish。
  • predict：每行输入 {"task": ..., "inputs": ...}，立即输出一行； 分类输出 [{"label": ..., "score": 0~1}]，回归输出 {"value": 非负有限数}。
  • 候选约束：最多 64 个文件、512MiB；本方案只提交一个小于 16MiB 的 checkpoint.npz。
  • 状态：每轮写 records.json（最近 50 条）与选中检查点，使用唯一目录名。

五、离线运行与目录边界

  • /app、/previous、/state 只读；训练与预测只在 /workspace 写文件。
  • /state 先用 rnd.state_workspace() 复制到可写目录，再读取 records.json。
  • 不使用隐藏测试集、不联网下载依赖、不读取环境中的账号密钥。
  • 平台模型通过 rnd.model() 访问；未配置本地传输层时无法离线驱动大模型，但工业模型训练与预测可离线完成。

R8 预期结果：A Accuracy 0.8543 / Macro F1 0.8499（第 8 轮产物，第 9/10 轮保留父产物）、 B RMSE 679.36、C RMSE 56.35；CPU 合计约 2,865s；Token 合计 35,355。 B 的可见复现链为 658.13 → 663.14 → 652.57，隐藏值与 R6/R7 逐位一致。 以上数值用于确认策略路径。

七、异常处理

  • 决策 JSON 解析失败或数值非法：回退到保守默认值，回合继续。
  • 漂移统计读取失败：写入 available=false 摘要，不阻塞训练。
  • 训练/提交异常：捕获异常，保留父产物并正常 finish；记录 failure 字段。
  • 候选提交返回空：强制保留父产物，state 不推进。
  • 状态文件损坏或记录非字典：清洗后按空历史处理。
  • 预测缓存按检查点路径区分，切换产物时不会复用旧模型。

八、回滚方法

  • 轮内回滚：A/C 主方案未优于父模型时，自动以 epochs/2、lr/2 重跑；仍不优则 keep_parent。
  • 历史最优保护：A 的候选需优于首轮基线与全部已采纳候选的最优可见值才推进， 否则保留父产物；连续 3 轮未采纳后停训。由于“父产物即上次采纳产物”， 保留父产物等价于锁定历史最优检查点。
  • 跨轮回滚：state 中保存的是“本轮选中检查点”，保留父产物即把该检查点写回 state； 平台最终产物以 finish(selected_artifact_id=父产物) 为准。
  • 预算止损：A 用满 10 次采纳、B 用满 3 次固定采纳、C 用满 1 次后停止训练，仅保留父产物。
  • 人工回退：重新以历史 checkpoint.npz 作为父产物运行；不覆盖旧目录，旧产物可直接复用。
  • 所有回滚均写入 records.json 的 selected、reason 与 configuration，可审计。
