## v1 SFT 数据构造

- 状态：initial / round1 / round2 三个历史快照 × A/B/C
- 网格：initial 12 组（epochs 1,2,3,5,8,10 × lr 0.0005,0.001）；
  round1/round2 各 8 组（epochs 1,2,5,10 × lr 0.0005,0.001）
- 标签：同一状态下验证指标最优的 epochs/learning_rate，答案文本由实测数值生成
- 产物：`experiments/sft/sft-v1.jsonl`、`experiments/sft/sft-v1_grids.json`
- 共 84 次真实训练（initial 12 组 + round1/round2 各 8 组，× A/B/C）

网格最优结果（父模型 → 网格最优）：

| 数据集 | 状态 | 最优 epochs / lr | before → after |
|---|---|---|---|
| A | initial | 2 / 0.001 | 0.7140 → 0.7187 |
| A | round1 | 10 / 0.001 | 0.7166 → 0.7182 |
| A | round2 | 1 / 0.001 | 0.7258 → 0.7268 |
| B | initial | 8 / 0.0005 | 681.16 → 651.04 |
| B | round1 | 5 / 0.0005 | 675.87 → 659.12 |
| B | round2 | 2 / 0.0005 | 669.87 → 663.87 |
| C | initial | 8 / 0.0005 | 52.869 → 51.670 |
| C | round1 | 2 / 0.001 | 52.122 → 51.591 |
| C | round2 | 10 / 0.001 | 51.635 → 51.433 |

观察：
- 最优学习率几乎总是 0.001（A、C）或 0.0005（B），且 B 的保守小学习率确实优于基线的激进大学习率。
- A 的最优轮数从 initial 的 2 轮升到 round1 的 10 轮再回落到 round2 的 1 轮，说明“最优策略随历史状态变化”，正是微调要学的东西。
- B 从父模型 681 直接降到 651，收益远大于基线自动回退后的 669。

- 修正：round2 状态最初误用被 safe_train 回退的尝试检查点（B 父模型 680.01），已改为使用状态输出检查点（B 父模型 669.87）重跑 24 组，上表为修正后数值。
- B round2 的最优只有 2 轮，进一步印证“同一数据集在不同历史状态下最优轮数差异很大”。

## v1 LoRA 微调

- 脚本：`tools/sft_train.py`；数据：9 条（3 状态 × A/B/C），每条为对话 + 实测最优答案
- 超参：LoRA rank 32，20 步，学习率 1e-4，全量 9 条作为一个 batch
- 权重：`trio://run_dx0l5u4clgcp/sampler_weights/aiplus-v1`
- SwanLab：sft-v1（run ucgifpo7）
- loss 曲线：1.677 → 1.512 → 1.284 → 1.050 → 0.828 → 0.601 → 0.413 → 0.270 → 0.195 → 0.173
  → 0.142 → 0.126 → 0.115 → 0.107 → 0.100 → 0.092 → 0.085 → 0.079 → 0.064 → 0.050
- 说明：9 条样本 20 步内 loss 降到 0.05，模型完全拟合训练标签；关注点转为泛化——用同一真实评测看它对未见状态的决策是否更稳。

### v1 评测对比（同一真实评测，2 轮 × 3 数据集）

SwanLab：llm-eval-sft-v1（run i57ta8xh，含权重路径）

| 数据集 | 版本 | 两轮累计 | 每轮决策 |
|---|---|---|---|
| A | 基线 | 0.7140 → 0.7258（+0.0118） | 5 轮 / 8 轮，lr 0.001 |
| A | SFT v1 | 0.7140 → 0.7193（+0.0053） | 2 轮 / 2 轮，lr 0.0005 |
| B | 基线 | 681.16 → 669.87（−11.29） | 10 轮；7 轮（回退后） |
| B | SFT v1 | 681.16 → 659.68（−21.47） | 2 轮 / 2 轮，0.0005 |
| C | 基线 | 52.869 → 51.635（−1.234） | 10 轮 / 15 轮 |
| C | SFT v1 | 52.869 → 51.670（−1.199） | 8 轮；2 轮失败回退父模型 |

结论：
- SFT v1 学会了“保守小步”，B 上收益翻倍（相对基线多降 10.2），但 A 明显欠训练（基线 8 轮 +0.0072，SFT 只 +0.0016）。
- 出现**模式坍缩**：每轮几乎都回答“2 轮 / 0.0005”，与状态无关；hypothesis 中的指标数值是训练标签里背下来的（如 B 的 69.1197），并非真实推理。
- 原因判断：9 条样本、20 步、lr 1e-4 过度拟合，模型只学到“模板 + 固定数字”，没学会“看状态做决策”。
- v2 方向：补充 SFT v1 自身轨迹上的新状态（每数据集再 2 个），把样本从 9 条扩到 15 条；降低拟合强度（减少步数/学习率），并在标签中保留足够多样的 epochs 分布。

## v2 数据与微调

- 数据来源：sft-v1 评测跑出的 6 个新状态（A/B/C 各 2 个），再跑 48 组网格标注
- 数据清洗：C 的两个新状态所有网格组合都劣于父模型（51.67 → 最优 51.88），按“无提升样本不进训练集”剔除，最终 13 条
- 标签分布：epochs 1/2/2/2/2/2/2/5/8/8/10/10/10，lr 0.0005 与 0.001 混合
- 超参：LoRA rank 32，10 步，学习率 5e-5；loss 1.503 → 0.568（刻意不拟合到 0）
- 权重：`trio://run_ibgiij7ethtz/sampler_weights/aiplus-v2`
- SwanLab：sft-v2（run efhtxlik）

### v2 评测对比（2 轮 × 3 数据集）

| 数据集 | 版本 | 两轮累计 | 每轮决策 |
|---|---|---|---|
| A | 基线 | +0.0118 | 5 轮 / 8 轮 |
| A | SFT v1 | +0.0053 | 2 / 2 |
| A | SFT v2 | +0.0031 | 2 / 2（lr 0.0001） |
| B | 基线 | −11.29 | 10 轮；7 轮回退 |
| B | SFT v1 | −21.47 | 2 / 2 |
| B | SFT v2 | **−27.74** | 2 / 2 |
| C | 基线 | −1.234 | 10 轮 / 15 轮 |
| C | SFT v1 | −1.199 | 8 轮；2 轮回退 |
| C | SFT v2 | −0.772 | 2 / 2 |

结论：
- v2 把 B 的累计收益做到 −27.74（相对基线接近 2.5 倍），说明“保守小步 + 数据集 B 用小学习率”的标注是有效的。
- 仍然存在模式坍缩：13 条样本、loss 只降到 0.568，模型依旧每轮都答“2 轮”，A 的后续增长和 C 的中等轮数都没学会。
- 判断：问题不在数据量本身，而在“状态 → 决策”的映射没有被模型当作条件依赖学习；v3 需要强状态差异（同一数据集不同阶段的最优轮数对比）+ 更小的拟合强度，或改用“给定候选让模型选择”的决策形式。

改进方向（待试运行验证）：
1. 采纳预算：每个数据集最多采纳 K 轮（A 重点，B/C 现有策略已自然收敛）。
2. 最小提升门槛：可见提升低于噪声阈值时不采纳，抑制验证集过拟合。
3. 预算用尽后仍每轮调用平台模型，但跳过训练、直接保留父产物，顺带降低 C 的耗时。
4. 用剩余 8 次试运行扫 K（如 1/3/5），以隐藏指标为唯一判据确认隐藏收益在哪个 K 见顶。

## 试运行 #3 提交失败与修复（2026-11-23 晚）

- 平台回执：提交不符合题意，要求“基于官方 baseline 和平台提供的父检查点续训，不要从头训练其他模型”；同时入口预检失败。

- 差异：R1、R2 同一段代码跑满 30 轮，说明宿主现在会预建 `state_out`（或工作区跨轮复用），旧写法不再安全。
- 修复：读取用唯一 `state_in-<uuid>` 目录；输出改为自建唯一 `state_out-<uuid>` 目录，写完 `records.json` + `checkpoint.npz` 后调用 `rnd.save_state`。不再对固定目录调用 `state_workspace`。
- 续训证据：提交的 configuration 新增 `resumed_from_parent: true` 和 `parent_checkpoint_sha256`；训练始终把平台父检查点作为 `resume` 传入，代码里不存在无 resume 的训练路径。
- 本地复现：`local_check.py` 现在每轮开跑前预建 `state_out` 目录模拟宿主；A/B/C 三分支全部通过，predict 正常。
